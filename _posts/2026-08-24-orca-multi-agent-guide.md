터미널에서 AI 에이전트 하나를 실행하는 것은 어렵지 않습니다. 하지만 두세 개를 동시에 돌리기 시작하면 금방 복잡해집니다. 어떤 세션이 무슨 작업 중인지, 무엇을 기다리는지, 어떤 파일을 바꿨는지 탭 제목만으로는 알기 어렵고, 같은 프로젝트에서 여러 에이전트가 파일을 고치면 변경 사항이 뒤섞이기도 합니다.

**Orca**는 이 문제를 해결하는 데스크톱 앱입니다. 프로젝트마다 여러 에이전트를 실행하고, 각 작업의 상태와 변경 내용을 한 화면에서 확인할 수 있습니다. 이 글에서는 설치 후 준비할 것부터 작업을 맡기고, 결과를 검토하고, 반영하는 흐름까지 차례로 정리합니다.

> 이 글은 Orca 1.4.237 버전, 인터페이스 언어 한국어 기준입니다. Orca는 거의 매일 업데이트되므로 메뉴 이름이나 위치가 조금 다를 수 있고, 일부 문구는 영어로 표시됩니다.

## Orca란?

Orca는 MIT 라이선스의 무료 오픈소스 앱이며, 자체 AI 모델은 없습니다. 내 컴퓨터에 설치된 Claude Code, Codex 같은 CLI 에이전트를 Orca 안의 터미널에서 실행하는 방식이라, 사용량도 각 도구의 구독에서 차감됩니다. Orca가 하는 일은 그 터미널들을 작업 단위로 묶고, 상태를 보여 주고, 결과를 검토할 화면을 제공하는 것입니다.

알아 둘 개념은 세 가지입니다.

| 개념 | 설명 |
|---|---|
| 프로젝트 | Orca에 등록한 폴더. 보통 Git 저장소 하나가 프로젝트 하나입니다. |
| 워크스페이스 | 작업 하나를 진행하는 공간. 프로젝트에서 갈라져 나온 별도의 폴더와 브랜치를 가집니다. |
| 탭 | 워크스페이스 안에서 여는 에이전트 터미널, 브라우저, diff 화면입니다. |

워크스페이스 폴더는 **Git 워크트리(worktree)** 로 만들어집니다. 워크트리는 저장소 하나를 여러 폴더에 동시에 체크아웃하는 Git 기능으로, 폴더마다 다른 브랜치를 씁니다. 덕분에 두 에이전트가 동시에 파일을 고쳐도 변경이 섞이지 않고, 마음에 드는 결과만 골라 반영할 수 있습니다. 워크트리 생성과 삭제는 Orca가 처리하므로 `git worktree` 명령을 직접 입력할 일은 없습니다.

## 설치와 초기 설정

### 설치

공식 사이트나 GitHub Releases에서 운영체제에 맞는 파일을 받아 설치합니다.

| 플랫폼 | 설치 방법 |
|---|---|
| macOS | Apple Silicon/Intel용 `.dmg` 또는 Homebrew |
| Windows | `orca-windows-setup.exe` |
| Linux | AppImage, `.deb`, `.rpm` |

```bash
# macOS (Homebrew)
brew install --cask stablyai/orca/orca
```

### 에이전트 준비

Orca는 에이전트 CLI를 대신 설치하거나 로그인해 주지 않습니다. 이미 설치된 CLI를 찾아 목록에 보여 주고, 선택하면 실행할 뿐입니다.

- **이미 `claude`나 `codex`를 쓰고 있다면** 따로 할 일이 없습니다. Orca가 CLI를 자동으로 감지하고, 각 CLI에 저장된 로그인 정보(`~/.claude`, `~/.codex`)를 그대로 사용합니다.
- **아직 설치하지 않았다면** Orca를 쓰기 전에 CLI를 설치하고, 터미널에서 한 번 실행해 로그인해 둡니다.

```bash
# Claude Code
curl -fsSL https://claude.ai/install.sh | bash
claude

# Codex
npm install -g @openai/codex
codex
```

감지 결과는 **설정 > 에이전트**에서 확인합니다. *설치됨*에는 감지된 에이전트와 실행 명령이, *설치 가능*에는 지원하지만 아직 설치되지 않은 에이전트가 표시됩니다. 링크 아이콘을 누르면 설치 문서가 열리고, 설치 후 새로고침하면 *설치됨*으로 옮겨집니다.

### 첫 실행 안내

처음 실행하면 세 단계의 안내 화면이 나옵니다.

1. **기본 에이전트**: 감지된 에이전트 중 새 작업에 기본으로 쓸 것을 고릅니다.
2. **테마**: 다크, 라이트, 시스템 설정 중 선택합니다.
3. **알림**: 에이전트가 작업을 마치거나 답을 기다릴 때의 알림과 소리를 정합니다.

마지막 단계에서 *첫 프로젝트 추가*를 누르면 바로 폴더를 등록할 수 있습니다.

> ⚠️ **Yolo 모드 주의**
> 첫 단계의 Yolo 모드는 기본으로 켜져 있습니다. 켜져 있으면 에이전트가 명령 실행이나 파일 수정을 묻지 않고 진행해서 작업이 멈추지 않습니다. 실행 명령에 `--dangerously-skip-permissions` 같은 플래그가 붙는 것도 이 때문입니다.
>
> 워크트리는 **파일 변경**만 격리할 뿐 **명령 실행**까지 격리하지는 않습니다. 배포나 데이터베이스처럼 외부에 영향을 주는 작업이 있는 저장소라면 **설정 > 에이전트 > 에이전트 권한**에서 *수동*으로 바꾸세요. (*Auto*는 Claude Code와 Codex에만 적용되며, 각 도구의 자동 검토 기능이 승인 여부를 판단합니다.)

### Orca 스킬 설치 (선택)

안내를 마치면 사이드바에 온보딩 체크리스트가 남는데, 그중 **에이전트에 Orca 스킬 제공** 단계는 자동으로 처리되지 않습니다.

스킬은 에이전트에게 Orca 사용법을 알려 주는 안내 파일입니다. 기본적인 작업 위임에는 필요 없고, 뒤에서 다룰 **오케스트레이션**을 쓸 때만 필요합니다. 설치하려면 *스킬 설치*를 누르고, 체크리스트 안 터미널에 입력된 명령을 Enter로 실행한 뒤 스킬을 넣을 에이전트를 고릅니다. 오케스트레이션용이라면 일을 나눠 줄 에이전트(예: Claude Code) 하나만 골라도 됩니다.

**설치 직후 상태 요약**

| 항목 | 설치 직후 | 직접 할 일 |
|---|---|---|
| CLI (Claude Code, Codex 등) | 설치되어 있으면 자동 감지 | 없으면 직접 설치 |
| CLI 로그인 | 저장된 로그인 그대로 사용 | 처음이면 CLI에서 한 번 로그인 |
| Orca 스킬 | 설치 안 됨 | 오케스트레이션을 쓰려면 설치 |

## 화면 구성

- **왼쪽 사이드바**: 프로젝트와 워크스페이스 목록. 위쪽에 검색, 작업(GitHub·Linear·Jira 이슈), 자동화, Orca 모바일이, 아래쪽에 설정과 워크스페이스 보드 버튼이 있습니다.
- **작업 영역**: 선택한 워크스페이스의 탭이 열리는 곳입니다.
- **분할 패인**: 탭을 나란히 배치한 영역입니다. 예를 들어 한쪽에 에이전트, 다른 쪽에 내장 브라우저를 띄울 수 있습니다.
- **오른쪽 사이드바**: 탐색기, 에이전트(세션 기록), 소스 제어, 체크(GitHub 검사 결과) 탭을 전환합니다.
- **상태 표시줄**: 에이전트별 사용량과 한도 초기화 시각, 절전 방지, 메모리 사용량, 실행 중인 터미널 수, 감지된 개발 서버 포트를 보여 줍니다. 마우스 오른쪽 버튼으로 표시 항목을 고를 수 있습니다.

탭 표시줄의 **+** 를 누르면 터미널, 브라우저, 마크다운 문서와 감지된 에이전트 목록이 나옵니다. 한 워크스페이스에서 Claude Code와 Codex를 함께 열어 둘 수도 있습니다.

탭을 패인 가장자리로 끌어다 놓거나, 오른쪽 클릭 > *탭을 분할로 이동*에서 방향을 고르면 화면이 나뉩니다. 배치는 워크스페이스별로 기억되므로 다른 작업에 갔다 와도 그대로 남아 있습니다.

**자주 쓰는 단축키**

| 동작 | macOS | Windows/Linux |
|---|---|---|
| 새 워크스페이스 | `Cmd+N` | `Ctrl+N` |
| 워크스페이스·탭 검색 | `Cmd+J` | `Ctrl+J` |
| 파일 검색 | `Cmd+P` | `Ctrl+P` |
| 새 터미널 탭 | `Cmd+T` | `Ctrl+T` |
| 새 브라우저 탭 | `Cmd+Shift+B` | `Ctrl+Shift+B` |

## 작업 시작하기

### 1. 프로젝트 추가

사이드바 *프로젝트* 옆의 폴더 아이콘을 누르고, 다음 중 하나를 고릅니다.

- **폴더 찾아보기**: 내 컴퓨터의 폴더 등록
- **URL에서 복제**: 원격 저장소 복제
- **새 프로젝트 만들기**: 빈 폴더에서 시작

Git 저장소를 추가하면 기본 브랜치가 기준이 되고, 이후 워크스페이스는 여기서 갈라져 나옵니다. Git 저장소가 아닌 폴더도 열 수 있지만, 이때는 터미널·에이전트·파일 확인만 되고 워크트리·diff·커밋 같은 Git 기능은 빠집니다. 나중에 `git init`과 첫 커밋을 하면 모든 기능을 쓸 수 있습니다.

### 2. 워크스페이스 만들기

사이드바의 **+** 또는 `Cmd+N`을 누르면 *작업 트리 만들기* 창이 열립니다.

- **프로젝트**: 워크스페이스를 만들 프로젝트
- **실행 위치**: 이 컴퓨터 또는 연결해 둔 원격 장비
- **다음에서 만들기**: 워크스페이스 이름 입력. GitHub·브랜치 탭에서 이슈, PR, 기존 브랜치로 시작할 수도 있습니다. 오른쪽의 `main`은 기준 브랜치입니다.
- **에이전트**: 첫 탭에서 실행할 에이전트. 비우면 빈 터미널로 시작합니다.
- **더 만들기**: 켜 두면 창이 닫히지 않아 같은 설정으로 연달아 만들 수 있습니다.

*작업 트리 만들기*를 누르면 `~/orca/workspaces/프로젝트/이름` 폴더에서 에이전트가 실행됩니다. 입력창에 프롬프트를 넣으면 작업이 시작됩니다.

브랜치 이름에는 기본으로 Git 사용자 이름이 붙어 `이름/add-dark-mode` 형태가 됩니다. 접두사는 **설정 > Git 및 소스 제어 > 브랜치 접두사**에서 바꾸거나 없앨 수 있습니다.

> 💡 **의존성 자동 설치**
> 새 워크스페이스는 깨끗한 체크아웃이라 `node_modules` 같은 설치 파일이 없습니다. 저장소에 `pnpm-lock.yaml` 같은 잠금 파일이 있으면, 처음 워크스페이스를 만들 때 설치 명령을 설정 스크립트로 저장할지 묻는 카드가 나타납니다. *저장*을 누르면 이후 워크스페이스마다 자동 실행됩니다.

### 3. 진행 상황 확인

워크스페이스는 사이드바에 카드로 표시됩니다. 카드에는 이름과 브랜치, 그 아래에 실행 중인 에이전트가 나오고, 에이전트 제목은 첫 프롬프트에서 자동으로 만들어집니다. 앞의 아이콘이 현재 상태입니다.

| 표시 | 상태 |
|---|---|
| 🟡 회전 링 | 작업 중 |
| 🟠 물음표 | 답변·권한 승인 대기 |
| ✅ 초록 체크 | 작업 완료 |
| 🔔 노란 종 | 확인하지 않은 결과 있음 |
| 🟢 초록 점 | 터미널 열림, 대기 중 |
| 🔴 빨간 점 | 실패 |

여러 작업을 돌릴 때는 **물음표와 종 표시부터 확인**하고, 작업 중인 것은 그대로 두면 됩니다. 에이전트가 작업을 마치거나 답을 기다리면 시스템 알림과 소리로 알려 주고, macOS에서는 Dock 아이콘에 미확인 개수가 표시됩니다.

작업이 많아지면 사이드바 아래 보드 아이콘으로 **워크스페이스 보드**를 엽니다. 모든 워크스페이스를 Todo / In progress / In review / Done 칸으로 보여 주고, 카드를 끌어다 놓아 단계를 바꿀 수 있습니다. 칸은 직접 정하는 진행 단계이고, 카드 안 아이콘은 위의 에이전트 상태입니다.

> 💡 **앱을 닫아도 에이전트는 계속 실행됩니다**
> 터미널은 백그라운드 프로세스로 돌아가고, 앱을 다시 열면 그동안의 출력과 함께 재연결됩니다. 컴퓨터를 재시작한 경우에도 워크스페이스와 탭 배치가 복원되며, 중단된 Claude Code·Codex 세션은 이전 대화로 이어서 실행할 수 있습니다.

## 결과 검토와 반영

### 내장 브라우저와 요소 주석

웹 화면 작업이라면 내장 브라우저로 결과를 확인합니다. 터미널에서 개발 서버를 실행하면 상태 표시줄에 포트가 나타나고, 새 브라우저 탭에서 그 주소를 엽니다. 브라우저 탭은 워크스페이스별로 분리되어 있어, 작업마다 다른 포트를 열어도 섞이지 않습니다.

주소 표시줄 오른쪽에는 두 가지 버튼이 있습니다.

- **조준점 아이콘 (페이지 요소 가져오기)**: 요소를 가리킨 뒤 `C`를 누르면 요소 정보가 복사되고, `S`를 누르면 스크린샷이 찍힙니다. 에이전트 입력창에 붙여 넣으면 됩니다.
- **말풍선 아이콘 (페이지 요소에 주석 달기)**: 요소를 클릭해 수정 내용을 적어 두었다가 에이전트에게 보냅니다.

주석 모드에서 요소를 클릭하고, *변경* 또는 *질문*을 고른 뒤 내용을 적어 *추가*합니다. 여러 요소에 번호를 붙여 남긴 다음 *보내기*로 받을 에이전트를 고르면 됩니다. 주석은 요소의 선택자, HTML, 계산된 CSS, 주변 내용과 함께 하나의 프롬프트로 전달되므로, **어떤 코드가 그 요소를 만드는지 몰라도 화면에서 가리키고 말로 요청하면 됩니다.**

### diff 검토와 메모

에이전트가 바꾼 내용은 오른쪽 사이드바의 **소스 제어** 탭에서 확인합니다. 파일을 클릭하면 diff 탭이 열립니다.

1. 고칠 줄의 번호 왼쪽에 마우스를 올려 **+** 를 누릅니다.
2. 수정 내용을 적고 *메모 추가*를 누릅니다.
3. 다른 줄도 같은 방식으로 메모합니다. 메모는 줄에 카드로 고정되고 개수가 표시됩니다.
4. 검토가 끝나면 도구 모음의 *AI notes* 옆 보내기 아이콘을 누릅니다.

이 파일의 메모만 보낼지, 보내지 않은 전체 메모를 보낼지 고른 다음 받을 에이전트를 선택합니다. **실행 중인 세션**을 고르면 작업한 에이전트에게, **새로운 agent**에서 Codex를 고르면 Claude Code가 만든 변경을 Codex에게 고치게 할 수도 있습니다.

메모는 파일 경로와 줄 번호가 붙은 하나의 프롬프트로 정리되어 전달됩니다. 하나씩 보내기보다 **검토를 다 마친 뒤 한 번에 보내는 편**이 에이전트가 방향을 잡기 쉽습니다.

### 커밋, 푸시, 정리

결과가 마음에 들면 소스 제어 탭에서 마무리합니다. 커밋 메시지를 직접 쓰거나 오른쪽 아이콘으로 AI 초안을 만든 뒤, 상태에 따라 바뀌는 기본 버튼으로 스테이지 → 커밋 → 푸시를 진행합니다. GitHub 계정을 연결해 두면 Orca 안에서 PR도 만들 수 있습니다.

반영이 끝난 워크스페이스는 사이드바에서 오른쪽 클릭 > *삭제*하면 폴더와 브랜치가 함께 지워집니다. 병합되지 않은 커밋이 있을 수 있는 브랜치는 Git이 지우지 않으므로, Orca가 따로 보여 주고 강제 삭제 여부를 묻습니다.

## 여러 에이전트 함께 쓰기

Claude Code와 Codex는 별개의 프로그램이라 Orca에서 나란히 실행해도 서로를 모릅니다. 직접 열어 둔 두 세션이 알아서 대화하지는 않으며, 결과를 주고받는 방법은 네 가지입니다.

| 방법 | 전달 방식 | 준비 |
|---|---|---|
| 같은 작업 비교 | 전달 없이 사람이 비교 | 없음 |
| 메모 보내기 | diff 메모를 다른 에이전트에 한 번 전달 | 없음 |
| 다른 에이전트에게 인계 | 대화 핵심을 새 세션에 한 번 전달 | 없음 |
| 오케스트레이션 | 지시·보고·질문을 계속 주고받음 | 조정자에 오케스트레이션 스킬 |

### 같은 작업 비교

같은 문제를 여러 에이전트에게 맡기고 결과를 비교하는 방법입니다.

1. 워크스페이스 창에서 *더 만들기*를 켜고, 에이전트만 바꿔 같은 기준 브랜치로 두세 개를 만듭니다.
2. 모두에게 같은 프롬프트를 입력합니다.
3. 끝나는 대로 diff를 열어 비교합니다.
4. 가장 나은 결과에 메모로 보완을 요청하고, 커밋·푸시한 뒤 나머지는 삭제합니다.

에이전트마다 틀리는 지점이 달라서, 한 에이전트에게 여러 번 다시 시키는 것보다 판단하기 쉽습니다. 결과가 같은 방향이면 맞을 가능성이 높고, **서로 갈리는 부분이 직접 확인해야 할 지점**입니다.

### 다른 에이전트에게 인계

대화가 길어져 응답 품질이 떨어졌거나, Claude Code로 하던 작업을 Codex로 이어 가고 싶을 때 씁니다. 에이전트 터미널 오른쪽 위의 인계 아이콘을 누르고, 이어받을 에이전트와 넘길 컨텍스트 범위를 고른 뒤 *새 세션 시작*을 누릅니다. 같은 워크스페이스에 새 세션이 열리고 지금까지의 핵심이 담긴 프롬프트가 전달됩니다. 원래 세션은 그대로 남습니다.

### 오케스트레이션

한 에이전트가 다른 에이전트들에게 일을 나눠 맡기고, 완료 보고를 받아 결과를 종합하는 기능입니다. 일을 나누는 쪽을 **조정자(Coordinator)**, 맡는 쪽을 **작업자(Worker)** 라고 부릅니다.

에이전트끼리 직접 대화하는 것이 아니라 모든 메시지가 Orca를 거칩니다. 조정자가 `orca` 명령으로 작업자를 실행해 지시하면, 작업자는 끝난 뒤 같은 방식으로 보고하거나 질문합니다.

**준비 사항**

- **조정자에게만 오케스트레이션 스킬이 필요합니다.** 스킬이 없으면 에이전트가 이 기능을 모르기 때문에, "Codex에게 맡겨 줘"라고 해도 직접 처리하거나 자체 서브 에이전트를 써 버릴 수 있습니다.
- **작업자에게는 스킬이 필요 없습니다.** Orca가 보고 방법을 지시 앞에 붙여 전달합니다. 이미 열어 둔 터미널을 작업자로 쓰라고 요청해도 됩니다.
- `orca` 명령은 Orca 안 터미널에 기본 포함되어 있습니다.

스킬 설치 상태는 **설정 > 오케스트레이션**에서 확인합니다. *설치되지 않음*이면 *설치*를 눌러 앞서 설명한 방법으로 설치하고 *재확인*을 누릅니다. 에이전트별 상태에서 조정자로 쓸 에이전트가 *미설치*만 아니면 됩니다.

준비가 끝나면 조정자에게 무엇을 어떻게 나눌지 설명하기만 하면 됩니다.

```text
orchestration 스킬을 사용해서 상품 검색 기능을 두 작업으로 나눠 진행해 줘.
상품 목록 위의 검색 입력창과 이름 필터링 로직은 Codex에게,
검색 결과가 없을 때 보여 줄 안내 문구와 스타일은 Claude에게
각각 새 워크스페이스에서 맡겨 줘.
두 작업이 끝나면 바뀐 내용을 정리해서 알려 줘.
```

Claude Code에서는 `/orchestration`으로 스킬을 직접 불러온 뒤 설명해도 됩니다.

요청을 받은 조정자는 작업 항목을 만들고, Codex와 Claude를 각각 새 워크스페이스에서 실행한 뒤 완료 보고를 받아 정리합니다. 작업자의 워크스페이스(예: `search-input-codex`, `search-empty-claude`)는 사이드바에 따로 추가되고, 각자의 브랜치에 커밋됩니다. 두 브랜치를 합치는 일은 조정자가 이어서 하기도 하고 먼저 묻기도 하니 마지막 정리 내용을 꼭 확인하세요.

> ⚠️ 작업자 CLI가 업데이트 안내 같은 화면에서 멈추면 지시가 전달되지 않을 수 있습니다. 실제로 이 글의 예시를 만들 때도 Codex 작업자가 업데이트 안내에서 멈춰 조정자가 다시 시작했습니다. 작업자 상태가 오래 바뀌지 않으면 해당 워크스페이스의 터미널을 직접 확인하세요.

## 그 밖의 기능

### 자동화

정해진 시각에 프롬프트를 실행하는 기능입니다. 사이드바의 **자동화**에서 템플릿(예: 일일 변경 리뷰)을 고르거나 *새 자동화*를 누릅니다. 왼쪽에 프롬프트를 쓰고, 오른쪽에서 실행 조건을 정합니다.

- **에이전트**: 실행할 에이전트
- **프로젝트·워크스페이스**: 기존 워크스페이스에서 실행할지, 매번 새로 만들지
- **세션**: 새로 시작할지, 이전 세션을 재사용할지
- **일정·시간**: 매일, 평일, 매주 등의 주기와 시각
- **유예 시간**: 컴퓨터가 꺼져 있어 놓친 실행을 지정한 시간 안에서 따라잡음

자동화는 등록한 컴퓨터가 켜져 있어야 실행됩니다. 프롬프트가 안정될 때까지는 일정 없이 수동 실행으로 결과를 확인한 뒤 일정을 켜는 것을 권합니다.

### 모바일과 원격 실행

**Orca 모바일 앱**(iOS, Android)을 연결하면 자리를 비운 동안에도 진행 상황을 보고 에이전트의 질문에 답할 수 있습니다. 사이드바 *Orca 모바일 > 시작하기*로 페어링 코드를 만들고, 앱의 *데스크톱 페어링*에서 스캔합니다. 같은 Wi-Fi나 Tailscale 네트워크라면 계정 없이 연결되고, 외부에서는 Orca 계정으로 로그인해 Orca Relay(베타)를 사용합니다.

**원격 장비**에서 에이전트를 실행할 수도 있습니다. **설정 > SSH 호스트**에 장비를 등록하면 워크스페이스 생성 시 *실행 위치*에서 고를 수 있으며, 에이전트와 Git은 원격에서 돌고 화면은 내 컴퓨터에 남습니다.

### Orca CLI

`orca` 명령으로 실행 중인 Orca를 명령줄에서 조작할 수 있습니다. Orca 안 터미널에서는 바로 쓸 수 있고, 외부 터미널에서 쓰려면 **설정 > 일반 > Orca CLI**에서 셸 명령을 등록합니다.

```bash
# 워크스페이스를 만들고 에이전트에게 작업 맡기기
orca worktree create --name fix-login --agent claude --prompt "로그인 실패 버그를 재현하고 수정해 줘"
orca worktree ps
```

화면에서 하는 일 대부분을 CLI로도 할 수 있지만, 사람이 직접 입력하기보다는 주로 에이전트가 사용합니다. 오케스트레이션에서 조정자가 작업자를 실행하고 보고를 받는 것도 이 명령으로 이루어집니다.
