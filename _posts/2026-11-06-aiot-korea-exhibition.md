## 들어가며

2026년 11월 3일부터 5일까지 서울 코엑스 Hall D에서 열린 **AIoT 국제전시회 2026**에 다녀왔습니다. 과학기술정보통신부가 주최하고 한국AI사물인터넷협회와 K.Fairs가 주관한 국내 유일의 AI·IoT 전문 전시회입니다.

이번 참관에서는 AI 모델 자체의 성능보다 **데이터 수집 → AI 분석·판단 → 실시간 모니터링 → 외부 시스템 연동 → 서비스 운영**까지 실제로 이어지는 사례에 집중했습니다. 전시된 기업이 많았지만, 이 글에서는 기술적으로 인상 깊었던 기업 위주로 정리합니다.

---

## 1. 산업 안전: 센서부터 디지털 트윈까지 하나로

### 스피랩 · 한컴유비마이크로 · 평행공간 공동 전시

**주제: AI 기반 실시간 밀폐 작업 관리 통합 디지털 안전 선도모델**

이번 전시에서 가장 인상적인 부스였습니다. 세 기업이 역할을 나눠 밀폐공간 작업 위험을 감지하고 대응하는 하나의 시스템을 구성했습니다.

| 기업 | 역할 | 핵심 기술 |
|---|---|---|
| 한컴유비마이크로 | 센서 계층 | 복합가스 감지기, 이동형 모니터링 장비 |
| 스피랩 | AI·관제 계층 | 엣지 AI 위험 판단, SHAP 기반 XAI, OCAP 대응 가이드 |
| 평행공간 | 시각화 계층 | GPS 기반 위험구역 3D 디지털 트윈 |

전체 흐름은 다음과 같습니다.

```
현장 가스 감지 → 데이터 수집·전송 → 엣지 AI 위험 판단
→ XAI 위험 요인 설명 → 통합 안전관제 → 3D 디지털 트윈 시각화
```

스피랩은 5종 가스 데이터로 위험등급을 산정하고, **SHAP으로 어떤 요인이 위험도에 영향을 줬는지 설명**한 뒤, **OCAP(Out of Control Action Plan) 기반으로 대응 가이드**까지 제시합니다. 시스템 구성도에는 PostgreSQL, Redis, FastAPI(REST + WebSocket) 같은 기술 스택도 표시되어 있었습니다.

단순 임계치 경보가 아니라 "왜 위험한지, 그래서 무엇을 해야 하는지"까지 전달한다는 점에서, AI 결과를 현장 작업자가 실제로 활용할 수 있는 형태로 설계한 사례라고 생각합니다.

### 코드비전: COVI AX PLATFORM

제조공정 검사 데이터를 AI로 분석하는 품질검사 플랫폼입니다. 시연 화면에서는 NG(불량) 판정과 함께 **Shape Analysis, Deviation Regions, Measurement Tests** 등 세부 검사 항목을 확인할 수 있었습니다.

AI가 "불량"이라는 결론만 내리는 것이 아니라, 어떤 기준에서 문제가 생겼는지를 세분화해 보여준다는 점이 좋았습니다. 품질검사 AI를 서비스로 만들려면 추론 모델만큼이나 **검사 이력 관리, 결함 시각화** 기능이 중요하다는 것을 보여주는 사례입니다.

## 2. AI 서비스와 인프라

### SK텔레콤: AI Human

같은 AI 휴먼 기술을 **실시간 상담사**와 **AI 아나운서** 두 가지 서비스로 구성한 전시였습니다.

```
[AI 상담사 - 실시간]
음성 → STT → LLM·RAG → TTS → 립싱크 → AI 휴먼 응답

[AI 아나운서 - 비실시간]
대본 → TTS → 자막 생성 → 립싱크 아바타 → 그래픽 적용 → MP4 출력
```

TTS, 립싱크, 아바타라는 공통 기술 요소를 목적에 따라 **실시간 대화 파이프라인**과 **배치형 영상 생성 파이프라인**으로 다르게 조합했다는 점이 설계 관점에서 흥미로웠습니다.

### 드란비: EdgeGuard

AI 실행 중 발생하는 **전력 피크와 발열을 소프트웨어로 제어**하는 Runtime 기술입니다. 하드웨어 변경을 최소화하고 실행 환경 차원에서 운영 효율을 높이는 접근입니다.

전시 자료에 제시된 수치는 다음과 같습니다.

- 전력 피크 초과 발생: 20건 → 0건
- 평균 전력 약 8.3% 절감

> ⚠️ 전시 자료에 표시된 실험 결과이며, 독립적으로 검증한 수치는 아닙니다.

AI 서비스 운영에서는 처리 속도나 GPU 사용률뿐 아니라 전력과 발열도 결국 운영 비용과 안정성에 직결됩니다. 모델도 하드웨어도 아닌 Runtime 계층을 공략한다는 점이 신선했습니다.

### KETI: 도시 기후변화 감시 디지털 트윈

실제 센서의 물리 데이터와 **가상 센싱 데이터를 통합**해 도시 디지털 트윈 위에서 기후변화 영향과 피해를 감시하는 플랫폼입니다. 디지털 트윈을 3D 시각화 도구가 아니라 데이터 분석 플랫폼으로 활용하려는 방향을 확인할 수 있었습니다.

## 3. 피지컬 AI: 모델에서 행동으로

### 노타AI: VLA Robotics Demo

VLA(Vision-Language-Action)는 시각 정보와 자연어 명령을 받아 로봇의 행동을 결정하는 모델입니다. VLM이 "보고 말하는" 데 그친다면, VLA는 그 결과를 **물리적 행동**으로 연결합니다.

모델 출력이 실제 움직임이 되는 만큼 추론 지연과 제어 안정성이 핵심 과제가 됩니다. 다만 사용 모델, 파라미터 규모, 추론 환경 같은 세부 사양은 현장에서 확인하지 못했습니다.

### 텔로스: TLS-ROAS

여러 종류의 로봇을 하나의 플랫폼에서 운영·관제하는 소프트웨어입니다. 지도 기반 화면에서 로봇 상태와 제어 항목을 통합 관리하는 형태였습니다.

노타AI가 **로봇 개체의 지능**을 다룬다면, 텔로스는 **로봇 군(群)의 운영**을 다룹니다. 로봇이 다양해질수록 이런 관제 계층의 중요성은 더 커질 것으로 보입니다.

## 4. AI 시스템도 결국 소프트웨어: 품질 검증

**코드마인드**는 CODEMIND CSI·CQI, Hatter SCA 등 정적 분석 기반 소스코드 품질관리 솔루션을, **슈어소프트**는 테스트 케이스·스크립트·결함·보고서까지 관리하는 테스트 관리 시스템과 KOLAS 국제공인시험기관으로서의 SW 시험성적서 발급 서비스를 소개했습니다.

AI 기능을 아무리 잘 만들어도, 이를 감싸는 시스템의 품질과 추적 가능성이 확보되지 않으면 실제 운영은 어렵습니다. AI 전시회에서 SW 테스트 기업을 만난 것이 오히려 균형 잡힌 시각을 주었습니다.

## 정리: 이번 전시에서 보인 흐름

| 관찰 | 대표 사례 |
|---|---|
| AI 모델 → AI 기반 **시스템**으로 확장 | 스피랩 공동 전시 |
| 판단 결과에 **설명과 대응**을 결합 | 스피랩 XAI + OCAP, 코드비전 |
| 성능만큼 중요한 **Runtime 운영 효율** | 드란비 |
| 개체 지능과 **운영 플랫폼**의 분리 | 노타AI, 텔로스 |
| 데이터와 연결된 **운영형 디지털 트윈** | 평행공간, KETI |

산업 현장에서 AI가 작동하는 구조는 대부분 다음 형태로 수렴했습니다.

```
IoT 센서·카메라 → 데이터 수집 → AI 분석·판단 → 결과 저장·전송 → 통합 관제 → 현장 대응
```

AI 모델은 이 파이프라인의 한 칸일 뿐이었습니다. 앞으로 산업용 AI 서비스에서는 모델 성능과 함께 **데이터 연동, 실시간 처리, 설명 가능성, 모니터링, 운영 자동화, 품질 검증**이 경쟁력을 좌우할 것이라고 생각합니다.

모델을 만드는 것만큼, 모델을 현장에 연결하고 안정적으로 돌리는 시스템 설계가 중요하다는 점을 다시 느낀 전시회였습니다.
